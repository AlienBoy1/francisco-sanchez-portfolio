*# 1. Purpose*



*This document defines the mandatory initialization procedure that every AI agent operating through Cursor shall execute before performing any engineering activity within the Francisco Sánchez Portfolio repository.*



*Repository initialization ensures that AI begins every task with sufficient engineering awareness, active governance, and validated execution context.*



*Initialization is mandatory.*



*No engineering work shall begin before successful repository initialization.*



*---*



*# 2. Objectives*



*Repository initialization aims to:*



*- Load repository knowledge.*

*- Activate engineering governance.*

*- Validate repository structure.*

*- Acquire required context.*

*- Detect applicable engineering standards.*

*- Prevent uninformed execution.*

*- Reduce engineering inconsistencies.*

*- Ensure deterministic behavior.*



*---*



*# 3. Initialization Philosophy*



*Every engineering task begins with understanding.*



*AI shall never assume repository state.*



*Repository initialization establishes a controlled execution environment before any engineering activity begins.*



*Initialization reduces assumptions and increases engineering accuracy.*



*---*



*# 4. Initialization Triggers*



*Repository initialization shall occur whenever:*



*- A new engineering session begins.*

*- A repository is opened.*

*- A new project is cloned.*

*- Repository structure changes significantly.*

*- Active engineering domain changes.*

*- Governance documentation changes.*

*- Context has expired.*

*- Explicit initialization is requested.*



*Initialization may also be repeated whenever engineering confidence decreases.*



*---*



*# 5. Initialization Workflow*



*Repository initialization follows the sequence below.*



*1. Repository Detection*

*2. Repository Validation*

*3. Documentation Discovery*

*4. Governance Loading*

*5. Context Acquisition*

*6. Rule Activation*

*7. Dependency Discovery*

*8. Active Task Classification*

*9. Execution Readiness Verification*



*Execution shall begin only after successful completion of every required step.*



*---*



*# 6. Repository Detection*



*AI shall identify:*



*- Repository root.*

*- Active branch.*

*- Project structure.*

*- Primary technologies.*

*- Configuration files.*

*- Documentation directories.*



*Repository detection establishes the engineering environment.*



*---*



*# 7. Repository Validation*



*Repository validation shall verify:*



*- Expected directory structure.*

*- Required configuration files.*

*- Documentation hierarchy.*

*- Naming conventions.*

*- Repository integrity.*



*Structural anomalies shall be reported before execution.*



*---*



*# 8. Documentation Discovery*



*AI shall discover all available engineering documentation.*



*Discovery includes:*



*- Governance documents.*

*- AI Governance.*

*- Brand documentation.*

*- Product documentation.*

*- Design System.*

*- Architecture.*

*- Development.*

*- Deployment.*

*- Cursor Rules.*

*- Other applicable domains.*



*Documentation availability shall determine execution confidence.*



*---*



*# 9. Governance Loading*



*Before implementation, AI shall load:*



*- Applicable Governance documents.*

*- AI Governance standards.*

*- Active engineering policies.*

*- Repository conventions.*

*- Architecture constraints.*



*Governance shall remain active throughout execution.*



*---*



*# 10. Context Acquisition*



*AI shall collect all relevant engineering context.*



*Context sources include:*



*- Documentation.*

*- Repository structure.*

*- Existing implementation.*

*- Active branch.*

*- Current task.*

*- Related files.*

*- Previous engineering decisions.*



*Only validated context shall be used.*



*---*



*# 11. Rule Activation*



*After context acquisition, AI shall activate only the Cursor Rules required for the current task.*



*Rule activation shall consider:*



*- Engineering domain.*

*- Repository location.*

*- File type.*

*- Active workflow.*

*- Current objective.*



*Inactive rules shall not influence execution.*



*---*



*# 12. Dependency Discovery*



*Before implementation, AI shall identify dependencies including:*



*- Internal modules.*

*- Shared components.*

*- APIs.*

*- Services.*

*- Libraries.*

*- Documentation references.*

*- Architectural relationships.*



*Dependency discovery reduces unintended side effects.*



*---*



*# 13. Task Classification*



*Every engineering task shall be classified before execution.*



*Supported classifications include:*



*- Documentation*

*- Development*

*- Architecture*

*- Refactoring*

*- Bug Fix*

*- Testing*

*- Review*

*- Deployment*

*- Research*

*- Maintenance*



*Task classification determines which execution rules become active.*



*---*



*# 14. Execution Readiness Verification*



*Before beginning work, AI shall confirm:*



*- Repository detected.*

*- Governance loaded.*

*- Documentation discovered.*

*- Context validated.*

*- Required rules activated.*

*- Dependencies identified.*

*- Task classified.*

*- Engineering confidence acceptable.*



*Only then is execution authorized.*



*---*



*# 15. Initialization Failure*



*Initialization fails whenever:*



*- Repository cannot be identified.*

*- Required documentation is missing.*

*- Governance cannot be loaded.*

*- Context is insufficient.*

*- Repository integrity cannot be verified.*

*- Critical dependencies remain unknown.*



*Initialization failure shall block engineering execution.*



*---*



*# 16. Recovery Procedure*



*When initialization fails, AI shall:*



*1. Identify the failure.*

*2. Explain its impact.*

*3. Request missing information.*

*4. Recommend corrective actions.*

*5. Retry initialization after corrections.*



*Engineering work shall resume only after successful recovery.*



*---*



*# 17. AI Operational Contract*



*## Responsibilities*



*Cursor shall:*



*- Detect repository state.*

*- Validate engineering environment.*

*- Load governance.*

*- Acquire context.*

*- Activate applicable rules.*

*- Verify execution readiness.*



*---*



*## Authorized Actions*



*Cursor may:*



*- Inspect repository structure.*

*- Discover documentation.*

*- Request missing context.*

*- Activate engineering rules.*

*- Delay execution until initialization completes.*



*---*



*## Restricted Actions*



*Cursor shall not:*



*- Begin implementation before initialization.*

*- Ignore missing governance.*

*- Assume undocumented repository state.*

*- Skip validation.*

*- Execute with insufficient context.*



*---*



*## Success Criteria*



*Initialization is successful when:*



*- Repository structure is validated.*

*- Documentation is available.*

*- Governance is active.*

*- Context is sufficient.*

*- Applicable Cursor Rules are loaded.*

*- Task classification is complete.*

*- Execution readiness is confirmed.*



*---*



*## Failure Conditions*



*Initialization fails when:*



*- Repository understanding is incomplete.*

*- Documentation cannot be located.*

*- Governance remains inactive.*

*- Context confidence is insufficient.*

*- Required execution rules cannot be activated.*



*---*



*## Escalation*



*Persistent initialization failures shall be escalated to the Project Owner before any engineering activity proceeds.*



*---*



*# 18. Governance*



*Repository Initialization is mandatory for every AI-assisted engineering session.*



*Future Cursor Rules, AI Agents, Prompt Libraries, and Development Workflows shall inherit this initialization procedure unless explicitly superseded by a newer approved standard.*
