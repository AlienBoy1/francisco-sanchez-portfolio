*# 1. Purpose*



*This document establishes the foundational principles governing Cursor Rules within the Francisco Sánchez Portfolio engineering ecosystem.*



*Cursor Rules transform engineering governance into executable operational behavior for Artificial Intelligence agents.*



*Their purpose is to ensure that every AI interaction consistently follows approved engineering standards, documentation, architectural decisions, and development practices.*



*Cursor Rules serve as the execution layer connecting governance with implementation.*



*---*



*# 2. Objectives*



*The Cursor Rules framework aims to:*



*- Transform governance into operational behavior.*

*- Standardize AI execution.*

*- Reduce inconsistent engineering decisions.*

*- Enforce repository standards automatically.*

*- Improve engineering productivity.*

*- Reduce prompt complexity.*

*- Support deterministic AI behavior.*

*- Enable scalable AI-assisted development.*



*---*



*# 3. Cursor Rules Philosophy*



*Engineering standards should not depend on human memory.*



*Whenever possible, engineering decisions shall be enforced automatically through Cursor Rules.*



*Rules exist to eliminate ambiguity rather than increase restrictions.*



*The best engineering process is one where correct behavior becomes the default behavior.*



*---*



*# 4. Scope*



*Cursor Rules apply to every AI-assisted engineering activity including:*



*- Software development.*

*- Documentation generation.*

*- Architecture decisions.*

*- Refactoring.*

*- Code reviews.*

*- Repository maintenance.*

*- Prompt execution.*

*- AI collaboration.*

*- Engineering analysis.*



*Every engineering task executed through Cursor shall comply with the applicable rules.*



*---*



*# 5. Execution Hierarchy*



*Cursor Rules shall respect the following precedence.*



*1. Governance Documents (GOV)*

*2. AI Governance (AIG)*

*3. Brand Documentation (BRD)*

*4. Product Documentation (PRD)*

*5. Design System (DS)*

*6. Architecture Documentation (ARC)*

*7. Development Documentation (DEV)*

*8. Deployment Documentation (DEP)*

*9. Cursor Rules (CUR)*

*10. Prompt Instructions*

*11. Current User Request*



*Higher-level governance shall always take precedence.*



*Cursor Rules shall never override approved documentation.*

*# 8. Rule Activation*



*Cursor Rules may be activated through:*



*- Repository context.*

*- Active engineering workflow.*

*- Engineering domain.*

*- File location.*

*- Current task.*

*- Explicit invocation.*



*Only relevant rules should be active during execution.*



*Rule minimization improves execution quality.*



*---*



*# 9. Rule Composition*



*Complex engineering activities shall compose multiple rules rather than relying on a single monolithic instruction.*



*Rules shall be:*



*- Modular.*

*- Independent.*

*- Reusable.*

*- Composable.*

*- Maintainable.*



*Small specialized rules are preferred over large generalized rules.*



*---*



*# 10. Rule Validation*



*Every Cursor Rule shall be validated for:*



*- Governance compliance.*

*- Architectural consistency.*

*- Engineering correctness.*

*- Deterministic behavior.*

*- Maintainability.*

*- Documentation synchronization.*



*Rules failing validation shall not be adopted.*



*---*



*# 11. Rule Quality Principles*



*Every Cursor Rule shall be:*



*- Explicit.*

*- Deterministic.*

*- Modular.*

*- Reusable.*

*- Versioned.*

*- Traceable.*

*- Maintainable.*

*- Technology-aware.*

*- Governance-compliant.*



*Ambiguous rules shall be considered engineering defects.*

*# 12. Rule Evolution*



*Cursor Rules shall evolve whenever:*



*- Governance changes.*

*- AI capabilities improve.*

*- Repeated engineering patterns emerge.*



*Rule evolution shall remain synchronized with documentation.*



*---*



*# 13. AI Operational Contract*



*## Responsibilities*



*Cursor Rules shall ensure that AI:*



*- Loads the correct documentation.*

*- Acquires sufficient context.*

*- Applies engineering standards.*

*- Follows architectural constraints.*

*- Produces deterministic outputs.*



*---*



*## Authorized Actions*



*Cursor Rules may:*



*- Activate additional engineering rules.*

*- Require documentation loading.*

*- Block invalid execution paths.*

*- Recommend workflow improvements.*

*- Enforce repository standards.*



*---*



*## Restricted Actions*



*Cursor Rules shall not:*



*- Override approved governance.*

*- Introduce undocumented standards.*

*- Ignore architecture constraints.*

*- Skip mandatory validations.*

*- Produce conflicting engineering behavior.*



*---*



*## Success Criteria*



*Successful Cursor Rule execution results in:*



*- Standards-compliant engineering.*

*- Consistent AI behavior.*

*- Predictable outputs.*

*- Reduced manual supervision.*

*- High repository consistency.*



*---*



*## Failure Conditions*



*Cursor Rule execution fails when:*



*- Governance is ignored.*

*- Rules conflict.*

*- Required documentation is omitted.*

*- AI behaves inconsistently.*

*- Engineering standards are violated.*



*---*



*## Escalation*



*Conflicts between Cursor Rules and approved documentation shall always be resolved in favor of the approved documentation and escalated to the Project Owner.*



*---*



*# 14. Governance*



*Cursor Rules are implementation mechanisms for AI Governance.*



*They operationalize, but never replace, engineering documentation.*



*Every Cursor Rule shall remain fully synchronized with:*



*- Governance Documents*

*- AI Governance*

*- Architecture Documentation*

*- Development Standards*

*- Repository Policies*



*Any inconsistency between rules and documentation shall be treated as a governance defect.*
