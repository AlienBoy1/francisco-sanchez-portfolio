*# 1. Purpose*



*This document defines the standard engineering workflow that every AI-assisted engineering activity shall follow within the Francisco Sánchez Portfolio ecosystem.*



*The Engineering Workflow establishes a deterministic sequence of phases that ensures consistency, quality, traceability, and governance compliance throughout the execution of every engineering task.*



*No engineering activity shall bypass this workflow.*



*---*



*# 2. Objectives*



*The Engineering Workflow aims to:*



*- Standardize engineering execution.*

*- Improve implementation quality.*

*- Reduce engineering defects.*

*- Ensure governance compliance.*

*- Increase execution predictability.*

*- Improve traceability.*

*- Enable repeatable engineering practices.*

*- Support scalable AI-assisted development.*



*---*



*# 3. Engineering Workflow Philosophy*



*Engineering is a controlled process rather than a sequence of isolated actions.*



*Every task shall progress through predefined workflow phases.*



*The workflow prioritizes correctness over speed and repeatability over improvisation.*



*---*



*# 4. Workflow Principles*



*Every engineering workflow shall be:*



*- Deterministic.*

*- Traceable.*

*- Incremental.*

*- Reviewable.*

*- Reproducible.*

*- Governed.*

*- Quality-driven.*

*- Continuously improvable.*



*---*



*# 5. Standard Workflow*



*Every engineering task shall follow the sequence below.*



*1. Task Understanding*

*2. Repository Initialization*

*3. Documentation Loading*

*4. Context Acquisition*

*5. Rule Activation*

*6. Engineering Analysis*

*7. Solution Design*

*8. Implementation*

*9. Validation*

*10. Review*

*11. Documentation Synchronization*

*12. Completion*



*Skipping workflow phases is prohibited unless explicitly authorized.*



*---*



*# 6. Phase Definitions*



*## Phase 1 — Task Understanding*



*AI shall identify:*



*- Engineering objective.*

*- Expected outcome.*

*- Constraints.*

*- Acceptance criteria.*

*- Scope.*



*Execution shall not continue until the objective is understood.*



*---*



*## Phase 2 — Repository Initialization*



*Execute CUR-1101.*



*---*



*## Phase 3 — Documentation Loading*



*Execute CUR-1102.*



*---*



*## Phase 4 — Context Acquisition*



*Execute CUR-1103.*



*---*



*## Phase 5 — Rule Activation*



*Execute CUR-1104.*



*---*



*## Phase 6 — Engineering Analysis*



*Analyze:*



*- Existing implementation.*

*- Dependencies.*

*- Risks.*

*- Architecture.*

*- Possible approaches.*



*No implementation shall begin before analysis.*



*---*



*## Phase 7 — Solution Design*



*Produce a solution consistent with:*



*- Architecture.*

*- Design System.*

*- Development standards.*

*- Repository conventions.*



*Design precedes implementation.*



*---*



*## Phase 8 — Implementation*



*Implementation shall:*



*- Respect architecture.*

*- Follow coding standards.*

*- Maintain readability.*

*- Preserve consistency.*

*- Avoid unnecessary complexity.*



*---*



*## Phase 9 — Validation*



*Validate:*



*- Functional correctness.*

*- Architectural compliance.*

*- Documentation consistency.*

*- Rule compliance.*

*- Repository integrity.*



*Validation is mandatory.*



*---*



*## Phase 10 — Review*



*Review shall evaluate:*



*- Engineering quality.*

*- Maintainability.*

*- Simplicity.*

*- Traceability.*

*- Governance compliance.*



*Review occurs before completion.*



*---*



*## Phase 11 — Documentation Synchronization*



*AI shall update affected documentation whenever implementation changes project knowledge.*



*Documentation shall remain synchronized with implementation.*



*---*



*## Phase 12 — Completion*



*Engineering execution concludes only when:*



*- Validation succeeds.*

*- Documentation is synchronized.*

*- Workflow completes successfully.*

*- Deliverables satisfy acceptance criteria.*



*---*



*# 7. Workflow Types*



*The standard workflow may specialize into:*



*- Feature Development*

*- Bug Resolution*

*- Refactoring*

*- Documentation*

*- Architecture*

*- Testing*

*- Deployment*

*- Repository Maintenance*

*- Research*



*Specialized workflows inherit this document.*



*---*



*# 8. Workflow Interruptions*



*Execution shall pause whenever:*



*- Governance conflicts arise.*

*- Context becomes insufficient.*

*- Repository integrity is compromised.*

*- Documentation becomes unavailable.*

*- Scope changes significantly.*



*Interrupted workflows shall resume only after resolution.*



*---*



*# 9. Workflow Quality Gates*



*Each workflow phase shall satisfy defined quality gates before progressing.*



*Quality gates include:*



*- Governance compliance.*

*- Context completeness.*

*- Rule consistency.*

*- Architecture compliance.*

*- Validation success.*



*Failure at any quality gate blocks progression.*



*---*



*# 10. Workflow Traceability*



*Every engineering workflow shall remain traceable through:*



*- Active task.*

*- Documentation references.*

*- Architecture decisions.*

*- Rule activations.*

*- Validation outcomes.*

*- Engineering deliverables.*



*Traceability supports long-term maintainability.*



*---*



*# 11. Continuous Improvement*



*Workflow improvements shall be driven by:*



*- Retrospectives.*

*- Engineering metrics.*

*- AI performance analysis.*

*- Repository evolution.*

*- Governance updates.*



*Changes require formal approval.*



*---*



*# 12. AI Operational Contract*



*## Responsibilities*



*Cursor shall:*



*- Follow every workflow phase.*

*- Respect quality gates.*

*- Synchronize documentation.*

*- Validate implementation.*

*- Complete execution deterministically.*



*---*



*## Authorized Actions*



*Cursor may:*



*- Recommend workflow improvements.*

*- Pause execution.*

*- Request clarification.*

*- Trigger validation.*

*- Suggest documentation updates.*



*---*



*## Restricted Actions*



*Cursor shall not:*



*- Skip workflow phases.*

*- Ignore quality gates.*

*- Complete work without validation.*

*- Leave documentation outdated.*

*- Override governance.*



*---*



*## Success Criteria*



*Workflow execution is successful when:*



*- All phases complete.*

*- Quality gates pass.*

*- Documentation is synchronized.*

*- Deliverables satisfy requirements.*

*- Engineering standards are preserved.*



*---*



*## Failure Conditions*



*Workflow execution fails when:*



*- Phases are skipped.*

*- Validation fails.*

*- Documentation becomes inconsistent.*

*- Governance is violated.*

*- Deliverables fail acceptance criteria.*



*---*



*## Escalation*



*Unresolved workflow failures shall be escalated to the Project Owner before execution continues.*



*---*



*# 13. Governance*



*This Engineering Workflow is mandatory for every AI-assisted engineering activity within the project.*



*Specialized workflows shall inherit this standard and may extend it without violating its principles.*
