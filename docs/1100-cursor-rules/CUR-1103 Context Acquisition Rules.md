*# 1. Purpose*



*This document defines the mandatory rules governing how Artificial Intelligence agents shall acquire, validate, refine, maintain, and evolve engineering context before executing any engineering activity within the Francisco Sánchez Portfolio ecosystem.*



*Context acquisition transforms repository knowledge into task-specific engineering understanding.*



*Execution without sufficient context is prohibited.*



*---*



*# 2. Objectives*



*Context Acquisition Rules aim to:*



*- Build task-specific engineering context.*

*- Reduce incorrect assumptions.*

*- Improve decision quality.*

*- Optimize context size.*

*- Increase execution determinism.*

*- Support engineering traceability.*

*- Prevent incomplete reasoning.*

*- Enable scalable AI execution.*



*---*



*# 3. Context Acquisition Philosophy*



*Engineering context is intentional.*



*Artificial Intelligence shall never attempt to maximize context quantity.*



*Instead, AI shall maximize context relevance.*



*The smallest complete context is preferred over the largest available context.*



*Context quality is more valuable than context volume.*



*---*



*# 4. Context Sources*



*Engineering context may be acquired from:*



*- Approved documentation.*

*- Active repository structure.*

*- Existing implementation.*

*- Repository configuration.*

*- Architecture definitions.*

*- Development workflows.*

*- Current engineering task.*

*- Valid engineering memory.*



*Documentation remains the primary source of context.*



*---*



*# 5. Context Hierarchy*



*When constructing engineering context, AI shall prioritize:*



*1. Governance (GOV)*

*2. AI Governance (AIG)*

*3. Cursor Rules (CUR)*

*4. Brand Documentation (BRD)*

*5. Product Documentation (PRD)*

*6. Design System (DS)*

*7. Architecture (ARC)*

*8. Development (DEV)*

*9. Deployment (DEP)*

*10. Existing implementation*

*11. Working memory*



*Lower-priority sources shall never override higher-priority sources.*



*---*



*# 6. Context Acquisition Workflow*



*Every engineering task shall construct context using the following sequence.*



*1. Identify engineering objective.*

*2. Determine affected engineering domains.*

*3. Load applicable documentation.*

*4. Retrieve relevant engineering memory.*

*5. Inspect existing implementation.*

*6. Discover dependencies.*

*7. Eliminate irrelevant information.*

*8. Validate context completeness.*

*9. Begin execution.*



*Context construction shall always precede implementation.*



*---*



*# 7. Context Classification*



*Engineering context shall be classified into:*



*## Mandatory Context*



*Required to safely execute the task.*



*Missing mandatory context blocks execution.*



*---*



*## Supporting Context*



*Improves engineering decisions but is not strictly required.*



*---*



*## Optional Context*



*Useful additional knowledge that may improve quality without affecting correctness.*



*---*



*# 8. Context Validation*



*Before execution, AI shall verify that context is:*



*- Relevant.*

*- Current.*

*- Complete.*

*- Consistent.*

*- Traceable.*

*- Approved.*

*- Sufficient.*



*Invalid context shall be discarded.*



*---*



*# 9. Context Optimization*



*AI shall continuously minimize unnecessary context.*



*Optimization techniques include:*



*- Removing unrelated domains.*

*- Eliminating duplicate information.*

*- Ignoring obsolete documentation.*

*- Prioritizing authoritative sources.*

*- Retaining only active engineering knowledge.*



*Context optimization improves execution efficiency.*



*---*



*# 10. Context Refresh*



*Engineering context shall be refreshed whenever:*



*- Repository structure changes.*

*- Active engineering task changes.*

*- Documentation changes.*

*- New dependencies appear.*

*- Architecture changes.*

*- Engineering confidence decreases.*



*Context shall evolve together with execution.*



*---*



*# 11. Context Consistency*



*Whenever conflicting context is detected, AI shall:*



*1. Identify the conflict.*

*2. Determine authoritative sources.*

*3. Apply governance hierarchy.*

*4. Discard obsolete context.*

*5. Report unresolved inconsistencies.*



*Context shall remain internally consistent.*



*---*



*# 12. Context Confidence*



*AI shall estimate context confidence before execution.*



*Confidence shall consider:*



*- Documentation availability.*

*- Governance coverage.*

*- Architecture completeness.*

*- Dependency visibility.*

*- Existing implementation quality.*

*- Context consistency.*



*Low confidence requires additional context acquisition.*



*---*



*# 13. Context Expiration*



*Engineering context shall expire whenever:*



*- Repository changes invalidate assumptions.*

*- Engineering domains change.*

*- Governance changes.*

*- Documentation changes significantly.*

*- Active workflow changes.*



*Expired context shall never guide engineering decisions.*



*---*



*# 14. AI Operational Contract*



*## Responsibilities*



*Cursor shall:*



*- Build engineering context.*

*- Validate context quality.*

*- Refresh outdated context.*

*- Detect missing information.*

*- Maintain contextual consistency.*



*---*



*## Authorized Actions*



*Cursor may:*



*- Acquire additional context.*

*- Refresh documentation.*

*- Request clarification.*

*- Eliminate irrelevant context.*

*- Delay execution until context becomes sufficient.*



*---*



*## Restricted Actions*



*Cursor shall not:*



*- Execute with incomplete mandatory context.*

*- Treat assumptions as context.*

*- Ignore governance hierarchy.*

*- Reuse expired context.*

*- Preserve contradictory engineering knowledge.*



*---*



*## Success Criteria*



*Context acquisition is successful when:*



*- Mandatory context is available.*

*- Documentation is synchronized.*

*- Dependencies are understood.*

*- Engineering confidence is sufficient.*

*- Context remains internally consistent.*



*---*



*## Failure Conditions*



*Context acquisition fails when:*



*- Mandatory documentation is unavailable.*

*- Context remains incomplete.*

*- Contradictory engineering information exists.*

*- Repository understanding is insufficient.*

*- Confidence remains below acceptable levels.*



*---*



*## Escalation*



*Persistent context deficiencies shall be escalated to the Project Owner before implementation proceeds.*



*---*



*# 15. Governance*



*Context Acquisition Rules are mandatory for every AI-assisted engineering task.*



*All future Cursor Rules, AI Agents, Prompt Libraries, and Development Workflows shall construct engineering context according to the principles defined herein unless superseded by a newer approved standard.*
