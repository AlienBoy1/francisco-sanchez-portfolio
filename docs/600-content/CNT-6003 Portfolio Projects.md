*# 1. Purpose*



*This document defines the official Portfolio Projects content specification for the Francisco Sánchez Portfolio.*



*It serves as the authoritative source of truth for every project showcased throughout the portfolio, ensuring consistency, traceability, and reusability across all platforms and presentation formats.*



*Every published project shall derive from this document.*



*---*



*# 2. Objectives*



*The Portfolio Projects content aims to:*



*- Showcase engineering capabilities through real projects.*

*- Demonstrate practical application of technical skills.*

*- Highlight architectural and engineering decisions.*

*- Present measurable project outcomes.*

*- Support recruiter and client evaluation.*

*- Enable structured content reuse.*

*- Maintain consistency across the portfolio ecosystem.*



*---*



*# 3. Content Philosophy*



*Projects are evidence of engineering capability.*



*Each project shall communicate not only what was built, but also why it was built, how it was designed, the challenges encountered, the decisions made, and the value delivered.*



*Descriptions shall prioritize technical substance over marketing language.*



*Claims shall be supported by demonstrable work.*



*---*



*# 4. Target Audience*



*The Portfolio Projects content is intended for:*



*- Technical recruiters.*

*- Hiring managers.*

*- Engineering managers.*

*- Software architects.*

*- Technical interviewers.*

*- Potential clients.*

*- Business partners.*

*- Software engineering peers.*



*---*



*# 5. Project Structure*



*Every portfolio project shall include the following sections.*



*| Section | Purpose |*

*|----------|---------|*

*| Project Name | Official project name. |*

*| Summary | High-level description. |*

*| Problem Statement | Business or technical problem addressed. |*

*| Solution Overview | General description of the implemented solution. |*

*| Role | Responsibilities assumed. |*

*| Technologies | Technology stack used. |*

*| Architecture | Relevant architectural decisions. |*

*| Features | Main capabilities delivered. |*

*| Challenges | Significant engineering challenges. |*

*| Results | Measurable outcomes or achievements. |*

*| Repository | Source code reference (when applicable). |*

*| Live Demo | Public deployment (when applicable). |*

*| Related Case Study | Link to detailed engineering documentation. |*



*The structure shall remain consistent across all portfolio projects.*



*---*

*Each project shall include, at minimum:*



*- Project Identifier.*

*- Name.*

*- Status.*

*- Category.*

*- Start Date.*

*- End Date.*

*- Visibility.*

*- Description.*

*- Objectives.*

*- Key Features.*

*- Responsibilities.*

*- Engineering Challenges.*

*- Results.*

*- Related Skills.*

*- Related Experience.*

*- Related Documents.*

*- Repository URL.*

*- Demo URL.*

*- Last Updated.*



*These attributes ensure traceability and interoperability across the portfolio.*



*---*



*# 7. Project Classification*



*Projects may be classified using one or more of the following categories.*



*| Category | Description |*

*|----------|-------------|*

*| Professional | Commercial or employer-sponsored work. |*

*| Personal | Independently developed projects. |*

*| Academic | University or educational work. |*

*| Open Source | Public collaborative development. |*

*| Research | Experimental or proof-of-concept initiatives. |*

*| Freelance | Client-specific solutions. |*



*Additional categories may be introduced as needed.*



*---*



*# 8. Content Sources*



*Project information shall originate from verified engineering artifacts, including:*



*- Source code repositories.*

*- Architecture documentation.*

*- Product documentation.*

*- Design documentation.*

*- Development documentation.*

*- Case studies.*

*- Release notes.*

*- Professional experience.*



*Project descriptions shall accurately reflect the implemented solution.*



*---*



*# 9. Version Control*



*Portfolio Projects content is version-controlled.*



*Updates shall occur whenever:*



*- A new project is added.*

*- A project reaches a significant milestone.*

*- New features are completed.*

*- Architectural decisions evolve.*

*- Public repositories or demos change.*

*- Project status changes.*



*Historical revisions shall remain traceable.*



*---*



*# 10. Governance*



*Portfolio Projects are official portfolio content assets.*



*Changes require:*



*- Technical validation.*

*- Documentation consistency review.*

*- Alignment with related engineering documents.*

*- Approval by the Project Owner.*



*All published project representations shall remain synchronized with this document.*

*Portfolio Projects shall comply with:*



*- Brand documentation.*

*- Product documentation.*

*- Architecture documentation.*

*- Development documentation.*

*Every published project shall maintain factual and technical accuracy.*
