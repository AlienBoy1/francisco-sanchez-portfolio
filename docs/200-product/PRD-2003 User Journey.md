*# 1. Purpose*



*This document defines how users interact with the Francisco Sánchez Portfolio from their first visit to the successful completion of their objectives.*



*Rather than describing pages, this document models complete user journeys based on user goals.*



*The objective is to ensure that every interaction contributes to a coherent, intuitive, and efficient user experience.*



*---*



*# 2. Journey Philosophy*



*The portfolio shall guide users toward their objectives with minimal cognitive effort.*



*Every navigation path should be intentional.*



*Every interaction should contribute to building professional trust.*



*Every journey should progressively reveal technical depth without overwhelming the visitor.*



*---*



*# 3. User Journey Lifecycle*



*Every journey follows the same high-level lifecycle.*



*```text*

*Discovery*

&#x20;     *↓*

*Landing*

&#x20;     *↓*

*Orientation*

&#x20;     *↓*

*Exploration*

&#x20;     *↓*

*Evidence*

&#x20;     *↓*

*Trust*

&#x20;     *↓*

*Action*

*```*



*---*



*# 4. Journey Stage: Discovery*



*The journey begins before the user enters the portfolio.*



*Possible entry points include:*



*- LinkedIn*

*- GitHub*

*- Resume*

*- Search Engines*

*- Direct URL*

*- Professional referral*

*- QR code*

*- Conference presentation*

*- Technical article*



*Success Criteria*



*The user arrives with clear expectations regarding professionalism.*



*---*



*# 5. Journey Stage: Landing*



*The landing experience should immediately answer:*



*- Who is this engineer?*

*- What does he build?*

*- Why should I continue exploring?*



*The first impression should communicate:*



*- Professionalism*

*- Engineering quality*

*- Clarity*

*- Trust*



*No unnecessary information should compete for attention.*



*---*



*# 6. Journey Stage: Orientation*



*Users should immediately understand:*



*- Navigation structure*

*- Available sections*

*- Main engineering projects*

*- Professional positioning*

*- Primary calls to action*



*Orientation should require minimal effort.*



*---*



*# 7. Journey Stage: Exploration*



*Users begin exploring based on their interests.*



*Examples include:*



*- Projects*

*- Case Studies*

*- Engineering Documentation*

*- Resume*

*- Skills*

*- Experience*

*- Blog*

*- Contact*



*The experience should support both quick scanning and deep exploration.*



*---*



*# 8. Journey Stage: Evidence*



*At this stage users seek proof.*



*Evidence may include:*



*- Production projects*

*- GitHub repositories*

*- Architecture documentation*

*- Engineering standards*

*- Case studies*

*- Technical articles*

*- Performance results*

*- Real implementations*



*Claims should always be supported by observable evidence whenever possible.*



*---*



*# 9. Journey Stage: Trust*



*Trust develops through consistency.*



*Factors contributing to trust include:*



*- Professional writing*

*- Consistent design*

*- Technical depth*

*- Working demonstrations*

*- Reliable navigation*

*- Accurate documentation*

*- Transparent engineering decisions*



*Trust should emerge naturally through the quality of the product.*



*---*



*# 10. Journey Stage: Action*



*Every journey should conclude with a meaningful action.*



*Examples include:*



*- Download Resume*

*- Visit GitHub*

*- Read a Case Study*

*- Contact Francisco*

*- Schedule an Interview*

*- Request Collaboration*

*- Explore Additional Projects*



*Every primary journey should end with a clear next step.*

*# 12. Journey Quality Principles*



*Every user journey should provide:*



*- Fast navigation.*

*- Clear information hierarchy.*

*- Progressive disclosure.*

*- Accessible interfaces.*

*- Consistent terminology.*

*- Minimal friction.*

*- Predictable interactions.*



*User effort should remain low throughout every journey.*



*---*



*# 13. Journey Completion Criteria*



*A successful journey is achieved when the user can accomplish their objective without confusion.*



*Completion indicators include:*



*- Resume downloaded.*

*- Contact established.*

*- Repository visited.*

*- Case study completed.*

*- Technical documentation explored.*

*- Interview requested.*

*- Collaboration initiated.*



*---*



*# 14. Governance*



*All future navigation decisions shall support one or more documented user journeys.*



*New features should improve existing journeys rather than introduce unnecessary complexity.*



*---*



*# 15. Compliance*



*Every major section of the portfolio shall contribute to at least one defined user journey.*



*Navigation paths that do not support a documented user objective should be reconsidered before implementation.*
