*# 1. Purpose*



*This document identifies the intended audiences of the Francisco Sánchez Portfolio and defines representative user personas.*



*Understanding user expectations enables product decisions that prioritize relevance, usability, and communication effectiveness.*



*The portfolio shall be designed around user needs rather than assumptions.*



*---*



*# 2. Audience Strategy*



*The portfolio serves multiple professional audiences.*



*Each audience has distinct objectives, technical knowledge, expectations, and decision-making criteria.*



*The product shall provide an efficient experience for each audience without compromising consistency.*



*---*



*# 3. Primary Audience*



*The primary audiences are:*



*- Recruiters*

*- Engineering Managers*

*- Technical Leads*

*- Software Architects*

*- CTOs*

*- CEOs*

*- Potential Clients*



*These audiences represent the primary decision-makers regarding professional opportunities.*



*---*



*# 4. Secondary Audience*



*Secondary audiences include:*



*- Software Engineers*

*- Students*

*- Open Source Contributors*

*- Technical Communities*

*- Collaborators*

*- Technology Enthusiasts*



*These users primarily seek technical knowledge, inspiration, or collaboration.*



*---*



*# 5. Persona: Technical Recruiter*



*## Goal*



*Determine whether the candidate should advance in the hiring process.*



*## Questions*



*- What technologies does this engineer use?*

*- What projects has he built?*

*- What level of experience does he demonstrate?*

*- Is there evidence of real work?*

*- Can I quickly access a résumé?*



*## Success Criteria*



*The recruiter can answer these questions within a few minutes of navigating the portfolio.*



*---*



*# 6. Persona: Engineering Manager*



*## Goal*



*Evaluate engineering maturity.*



*## Questions*



*- Does the candidate understand software architecture?*

*- Can the candidate maintain production systems?*

*- Does documentation exist?*

*- Are engineering practices evident?*

*- Is the codebase organized?*



*## Success Criteria*



*The portfolio demonstrates disciplined engineering practices supported by evidence.*



*---*



*# 7. Persona: Technical Lead*



*## Goal*



*Assess technical decision-making and implementation quality.*



*## Questions*



*- How are engineering decisions documented?*

*- What architectural trade-offs were considered?*

*- Is the implementation maintainable?*

*- How is quality ensured?*

*- Are modern engineering practices applied?*



*## Success Criteria*



*Technical documentation and architecture clearly communicate engineering reasoning.*



*---*



*# 8. Persona: CTO / CEO*



*## Goal*



*Evaluate business value and long-term potential.*



*## Questions*



*- Can this engineer solve business problems?*

*- Does the portfolio reflect professionalism?*

*- Can this person own complex projects?*

*- Is there evidence of leadership and initiative?*



*## Success Criteria*



*The portfolio demonstrates technical capability aligned with business impact.*



*---*



*# 9. Persona: Potential Client*



*## Goal*



*Determine whether the engineer can successfully deliver a software project.*



*## Questions*



*- What services are offered?*

*- What similar projects have been completed?*

*- What technologies are available?*

*- Is communication professional?*

*- How can contact be established?*



*## Success Criteria*



*The client quickly understands the engineer's capabilities and can easily initiate communication.*



*---*



*# 10. Persona: Software Engineer*



*## Goal*



*Learn from the engineering work and evaluate technical quality.*



*## Questions*



*- How was the system designed?*

*- What technologies were selected?*

*- What architectural decisions were made?*

*- Is the documentation comprehensive?*

*- Can implementation details be explored?*



*## Success Criteria*



*The portfolio provides meaningful technical depth beyond visual presentation.*



*---*



*# 11. Shared User Expectations*



*Regardless of audience, users expect:*



*- Fast loading.*

*- Clear navigation.*

*- Professional presentation.*

*- Responsive design.*

*- Accessible content.*

*- Accurate information.*

*- Consistent communication.*

*- Reliable links.*



*These expectations establish the baseline quality of the product.*



*---*



*# 12. User Priorities*



*The product prioritizes user needs in the following order:*



*1. Understanding professional capabilities.*

*2. Accessing supporting evidence.*

*3. Navigating efficiently.*

*4. Discovering technical depth.*

*5. Establishing professional contact.*



*Product decisions shall reinforce these priorities.*



*---*



*# 13. User Experience Principles*



*Every audience should experience:*



*- Minimal cognitive load.*

*- Predictable navigation.*

*- Progressive disclosure of technical detail.*

*- Clear calls to action.*

*- Consistent visual hierarchy.*

*- Accessible interfaces.*



*Complexity should be revealed gradually based on user interest.*



*---*



*# 14. Governance*



*New audience segments may be introduced as the portfolio evolves.*



*Future additions shall preserve the clarity and usability of the existing user experience.*



*---*



*# 15. Compliance*



*Every significant feature introduced into the product should support at least one defined audience.*



*Features that serve no identified user need should be reconsidered before implementation.*
