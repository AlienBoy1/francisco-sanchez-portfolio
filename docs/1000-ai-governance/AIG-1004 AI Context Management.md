*# 1. Purpose*



*This document establishes the standards for acquiring, validating, prioritizing, maintaining, and utilizing engineering context throughout every Artificial Intelligence interaction within the Francisco Sánchez Portfolio ecosystem.*



*Engineering quality depends directly on context quality.*



*Every engineering artifact generated by AI shall be based on sufficient, validated, and relevant context.*



*Context shall be treated as a governed engineering resource rather than temporary conversational information.*



*---*



*# 2. Objectives*



*The AI Context Management framework aims to:*



*- Ensure AI operates using complete engineering context.*

*- Reduce incorrect assumptions.*

*- Improve decision quality.*

*- Preserve architectural consistency.*

*- Increase deterministic behavior.*

*- Enable context sharing across specialized AI agents.*

*- Support long-term maintainability.*

*- Improve engineering traceability.*



*---*



*# 3. Context Philosophy*



*Engineering context is the operational knowledge required to make correct engineering decisions.*



*AI shall never assume context that has not been explicitly provided or documented.*



*Missing context shall be identified, documented, and escalated when necessary.*



*The quality of AI outputs shall always be proportional to the quality of available context.*



*---*



*# 4. Context Hierarchy*



*AI shall prioritize engineering context according to the following hierarchy.*



*1. Approved Governance Documents (GOV)*

*2. AI Governance Documents (AIG)*

*3. Brand Documentation (BRD)*

*4. Product Documentation (PRD)*

*5. Design System Documentation (DS)*

*6. Architecture Documentation (ARC)*

*7. Development Documentation (DEV)*

*8. Deployment Documentation (DEP)*

*9. Content Documentation (CNT)*

*10. Case Studies (CS)*

*11. Repository Source Code*

*12. Repository Configuration*

*13. Current Task Instructions*

*14. Conversational Context*



*Higher-priority context shall always override lower-priority information.*



*---*



*# 5. Context Categories*



*Engineering context shall be classified into the following categories.*



*## Strategic Context*



*Defines why the project exists.*



*Examples:*



*- Vision*

*- Mission*

*- Business goals*

*- Brand identity*

*- Product strategy*



*---*



*## Architectural Context*



*Defines how the system is organized.*



*Examples:*



*- System architecture*

*- Component hierarchy*

*- Routing*

*- APIs*

*- State management*



*---*



*## Implementation Context*



*Defines how engineering artifacts are implemented.*



*Examples:*



*- Naming conventions*

*- Folder structure*

*- Design tokens*

*- Coding standards*

*- Templates*



*---*



*## Operational Context*



*Defines how engineering activities are executed.*



*Examples:*



*- Sprint planning*

*- Workflows*

*- Deployment*

*- Quality Gates*

*- CI/CD*



*---*



*## Task Context*



*Defines information specific to the current engineering activity.*



*Examples:*



*- User request*

*- Files involved*

*- Constraints*

*- Expected output*



*---*



*# 6. Context Acquisition*



*Before beginning any engineering task, AI shall identify and collect all relevant context.*



*This includes:*



*- Applicable documentation.*

*- Repository structure.*

*- Existing implementation.*

*- Engineering standards.*

*- User instructions.*

*- Dependencies.*

*- Previous engineering decisions.*



*Context collection shall precede implementation.*



*---*



*# 7. Context Validation*



*Collected context shall be validated before use.*



*Validation shall confirm:*



*- Relevance.*

*- Completeness.*

*- Consistency.*

*- Authority.*

*- Version compatibility.*



*Outdated or conflicting context shall not be treated as authoritative.*



*---*



*# 8. Context Lifecycle*



*Engineering context progresses through the following lifecycle.*



*1. Acquisition*

*2. Classification*

*3. Validation*

*4. Application*

*5. Update*

*6. Archival*



*Context shall remain synchronized with repository evolution.*



*---*



*# 9. Context Sharing*



*Specialized AI agents shall exchange structured engineering context.*



*Shared context shall include:*



*- Current objective.*

*- Relevant documentation.*

*- Architectural constraints.*

*- Dependencies.*

*- Previous decisions.*

*- Risks.*

*- Pending actions.*



*Context shall remain consistent across every collaborating AI agent.*



*---*



*# 10. Context Preservation*



*During long engineering sessions, AI shall preserve critical context including:*



*- Approved decisions.*

*- Engineering assumptions.*

*- Architectural constraints.*

*- Active objectives.*

*- Outstanding issues.*

*- Document references.*



*Loss of critical context shall be treated as an engineering risk.*



*---*



*# 11. Context Refresh*



*Whenever significant repository changes occur, AI shall refresh affected context.*



*Refresh triggers include:*



*- Documentation updates.*

*- Architecture modifications.*

*- Design System changes.*

*- Technology migrations.*

*- Governance revisions.*

*- Major implementation changes.*



*AI shall avoid relying on obsolete engineering context.*



*---*



*# 12. Context Limitations*



*When required context is unavailable, AI shall:*



*1. Identify missing information.*

*2. Explain the impact.*

*3. Request clarification.*

*4. Delay irreversible engineering decisions until sufficient context exists.*



*Assumptions shall never replace missing engineering documentation.*



*---*



*# 13. AI Operational Contract*



*## Responsibilities*



*- Acquire relevant context.*

*- Validate context before use.*

*- Preserve engineering context.*

*- Share context with collaborating agents.*

*- Refresh context when necessary.*



*---*



*## Authorized Actions*



*AI may:*



*- Request additional context.*

*- Ignore obsolete information.*

*- Prioritize authoritative documentation.*

*- Recommend documentation improvements.*

*- Escalate missing context.*



*---*



*## Restricted Actions*



*AI shall not:*



*- Invent undocumented context.*

*- Ignore authoritative documentation.*

*- Use obsolete standards knowingly.*

*- Override higher-priority context.*

*- Continue when critical engineering context is missing.*



*---*



*## Success Criteria*



*Successful context management shall produce:*



*- Complete engineering understanding.*

*- Consistent AI behavior.*

*- Deterministic engineering outputs.*

*- Reduced implementation ambiguity.*

*- Traceable engineering decisions.*



*---*



*## Failure Conditions*



*Context management is considered unsuccessful when:*



*- Critical documentation is ignored.*

*- Obsolete information is used.*

*- Conflicting context remains unresolved.*

*- AI produces decisions unsupported by available evidence.*

*- Context is lost between collaborating agents.*



*---*



*## Escalation*



*If critical engineering context cannot be obtained, AI shall escalate to the Project Owner before proceeding.*



*---*



*# 14. Governance*



*Every AI agent shall perform context acquisition and validation before executing any engineering activity.*



*Context management is mandatory for all AI-assisted engineering tasks.*



*Specialized AI agents may extend this framework but shall not weaken its requirements.*
