*# 1. Purpose*



*This document establishes the engineering standard for designing, organizing, validating, maintaining, and evolving prompts used throughout the Francisco Sánchez Portfolio engineering ecosystem.*



*Prompts are considered engineering artifacts.*



*They shall be designed, reviewed, versioned, documented, and governed with the same rigor applied to source code and engineering documentation.*



*---*



*# 2. Objectives*



*The AI Prompt Engineering Standard aims to:*



*- Standardize prompt construction.*

*- Improve response consistency.*

*- Reduce ambiguity.*

*- Increase reproducibility.*

*- Enable prompt reuse.*

*- Improve maintainability.*

*- Support prompt versioning.*

*- Preserve engineering governance.*



*---*



*# 3. Prompt Engineering Philosophy*



*Prompts are executable engineering specifications.*



*A prompt shall communicate:*



*- Objective.*

*- Context.*

*- Constraints.*

*- Expected behavior.*

*- Expected output.*

*- Quality expectations.*



*A prompt shall never rely on implicit assumptions.*



*The quality of AI outputs depends directly on the quality of prompt design.*



*---*



*# 4. Prompt Hierarchy*



*Prompt execution shall respect the following hierarchy.*



*1. Engineering Documentation*

*2. AI Governance*

*3. Cursor Rules*

*4. Agent Definition*

*5. Workflow Definition*

*6. Prompt Specification*

*7. Current Task*



*Prompts shall never override approved engineering governance.*



*---*



*# 5. Prompt Structure*



*Every engineering prompt should contain the following sections.*



*## Objective*



*Defines the engineering goal.*



*---*



*## Context*



*Provides all required engineering information.*



*---*



*## Constraints*



*Defines limitations that cannot be violated.*



*---*



*## Inputs*



*Specifies available information.*



*---*



*## Expected Outputs*



*Defines the expected deliverables.*



*---*



*## Success Criteria*



*Defines when execution is considered successful.*



*---*



*## Validation Requirements*



*Defines engineering standards that must be verified before completion.*



*---*



*# 6. Prompt Categories*



*Engineering prompts shall be classified into:*



*## Strategic Prompts*



*Used for:*



*- Architecture*

*- Planning*

*- Governance*

*- Product decisions*



*---*



*## Analytical Prompts*



*Used for:*



*- Code review*

*- Architecture review*

*- Performance analysis*

*- Security analysis*



*---*



*## Implementation Prompts*



*Used for:*



*- Component generation*

*- API generation*

*- Documentation generation*

*- Refactoring*

*- Testing*



*---*



*## Operational Prompts*



*Used for:*



*- Automation*

*- Deployment*

*- Maintenance*

*- CI/CD*

*- Release activities*



*---*



*# 7. Prompt Design Principles*



*Every engineering prompt shall satisfy the following principles.*



*## Clarity*



*Objectives shall be explicit.*



*---*



*## Completeness*



*Required information shall be provided.*



*---*



*## Determinism*



*Equivalent inputs should produce equivalent outputs.*



*---*



*## Traceability*



*Prompts shall reference applicable documentation whenever possible.*



*---*



*## Reusability*



*Prompt design shall encourage reuse.*



*---*



*## Maintainability*



*Prompts shall be easy to modify without changing their purpose.*



*---*



*## Modularity*



*Large prompts should be composed of smaller reusable sections.*



*---*



*# 8. Prompt Lifecycle*



*Engineering prompts follow the lifecycle below.*



*1. Design*

*2. Review*

*3. Validation*

*4. Approval*

*5. Execution*

*6. Improvement*

*7. Version Update*

*8. Retirement*



*Prompt evolution shall remain governed.*



*---*



*# 9. Prompt Validation*



*Before execution, AI shall verify that the prompt contains:*



*- Clear objective.*

*- Sufficient context.*

*- Defined constraints.*

*- Required references.*

*- Expected outputs.*

*- Success criteria.*



*Incomplete prompts shall be refined before execution whenever possible.*



*---*



*# 10. Prompt Quality Principles*



*Engineering prompts shall be:*



*- Specific.*

*- Unambiguous.*

*- Context-aware.*

*- Deterministic.*

*- Maintainable.*

*- Reusable.*

*- Governed.*

*- Documented.*



*---*



*# 11. Prompt Reuse*



*Prompt reuse is encouraged.*



*Reusable prompts shall:*



*- Solve recurring engineering problems.*

*- Remain technology agnostic whenever possible.*

*- Reference documentation instead of duplicating it.*

*- Minimize maintenance costs.*



*---*



*# 12. Prompt Versioning*



*Engineering prompts shall follow Semantic Versioning.*



*Version updates shall occur whenever:*



*- Engineering behavior changes.*

*- Standards evolve.*

*- Documentation changes.*

*- New engineering capabilities are introduced.*



*Prompt history shall remain traceable.*



*---*



*# 13. AI Operational Contract*



*## Responsibilities*



*- Interpret prompts consistently.*

*- Validate prompt completeness.*

*- Respect documented constraints.*

*- Produce deterministic outputs.*

*- Recommend prompt improvements.*



*---*



*## Authorized Actions*



*AI may:*



*- Refine prompt wording.*

*- Request missing context.*

*- Recommend reusable prompt patterns.*

*- Suggest prompt modularization.*

*- Detect ambiguous instructions.*



*---*



*## Restricted Actions*



*AI shall not:*



*- Ignore documented constraints.*

*- Invent undocumented objectives.*

*- Execute contradictory prompts.*

*- Treat incomplete prompts as complete.*

*- Override engineering governance.*



*---*



*## Success Criteria*



*Successful prompt execution shall produce:*



*- Predictable outputs.*

*- Standards-compliant artifacts.*

*- Engineering consistency.*

*- High-quality deliverables.*

*- Complete traceability.*



*---*



*## Failure Conditions*



*Prompt execution is considered unsuccessful when:*



*- Objectives remain ambiguous.*

*- Context is insufficient.*

*- Outputs violate engineering standards.*

*- Prompt behavior becomes inconsistent.*

*- Prompt execution is not reproducible.*



*---*



*## Escalation*



*When prompt ambiguity cannot be resolved through documentation, AI shall request clarification from the Project Owner before continuing.*



*---*



*# 14. Governance*



*Every prompt used within the engineering ecosystem shall comply with this standard.*



*Prompt libraries, agent instructions, Cursor Rules, and engineering workflows shall inherit these principles.*
